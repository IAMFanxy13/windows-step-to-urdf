# Contributing

Contributions are welcome.

1. Discuss substantial product or schema changes in an Issue first.
2. Add a failing regression test before a bug fix or domain-behaviour change.
3. Keep exact geometry, estimates, recommendations, template matches, and user-entered values distinguishable.
4. Do not weaken export Blockers merely to make an example pass.
5. Run `npm run verify` and report the commands, versions, and untested cases.
6. Do not add private CAD, screenshots, absolute paths, credentials, generated job data, or unlicensed assets.
7. Keep beginner-facing copy separate from stable domain identifiers and schemas.

Pull requests should explain the user problem, evidence, schema impact, tests, screenshots for UI changes, third-party license impact, and rollback path. Contributions are accepted under Apache-2.0.
